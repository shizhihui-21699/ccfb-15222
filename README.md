# Aegis — 服务端权威移动/战斗判定（参考实现 + 压测）

一个可直接运行的 Elixir 参考实现，演示如何把"直接相信客户端"的服务器改成**服务端权威判定**，
并且为了不误伤卡顿玩家，判定逻辑刻意区分了"网络抖动"和"外挂"两类信号。

> 这个仓库不是完整游戏服务器，而是**判定内核**（纯函数）+ **离散事件压测**。
> 判定内核不依赖任何传输层，可以嵌进现有的 gen_server / ECS / Phoenix Channel 里。

## 30 秒上手

```bash
mix test                      # 41 个单元测试
mix run scripts/bench.exs     # 判定内核单核吞吐（微基准）
mix run scripts/stress.exs    # 默认 200 正常玩家 + 170 外挂，30 秒
```

压测真实网络参数：

```bash
# 120ms 延迟、80ms 抖动、8% 丢包
mix run scripts/stress.exs --honest 200 --seconds 20 --latency 120 --jitter 80 --loss 0.08
# 只测某一类外挂
mix run scripts/stress.exs --cheats speed:20,teleport:20
```

## 核心设计

### 1. 移动判定：两层时间轴，抖动免疫

**难点**：网络延迟/丢包让包的"到达间隔"忽长忽短。如果按到达间隔给位移额度，
正常玩家会被误判成加速。

**做法**：位移额度按 **客户端自己的帧距 `client_ts`** 累积，而不是到达间隔。
丢包、乱序、抖动只扭曲到达间隔，不扭曲客户端两帧之间的时间差，所以正常玩家
`sum(delta) == 速度 × 时间` 恒成立。

同时用三条约束叠加（见 `lib/aegis/validator.ex` `do_move/5`）：

| 约束 | 时钟 | 作用 |
|---|---|---|
| 逐包桶 `bucket` | 客户端帧距 | 允许网络停顿后一次性补回，上限 `budget_cap` |
| 客户端窗口 `cwin` | 客户端时间轴 | 主预算，`win_ms` 内的累计位移 |
| 服务端窗口 `swin` | 服务端真实时间 | 兜底：防伪造时钟，篡改只能骗过前两者之一 |

客户端时间轴被**钳制**在真实时间附近（`max_clock_lead`），所以"把时钟调快换速度"
在 `swin` 上必然暴露。

### 2. 墙体判定：几何绝对约束

- 位置必须落在可行走格子内（栅格地图 + DDA 扫掠，`Aegis.Map`）。
- 两点连线被墙挡住时，用**有界 Dijkstra** 判断是否存在"合理绕行"
  （`direct + margin` 以内）。正常玩家抄近道只差一两米；穿墙要么完全不可达，
  要么绕行极远。
- 扫掠被挡但绕行代价超过阈值才算违规，所以"贴墙走"不会误判。
- 位移超预算、且横向跨墙时，即使距离小也按墙处理；单次巨大跳跃记为瞬移。
- 传送门、击退等**合法位移**由服务端事件产生，以 `grant` 额度记账，不参与预算惩罚。

### 3. 战斗判定：延迟补偿

- **攻击者位置**用服务端权威位置（或回退窗口内的历史位置）。攻击包若比攻击者自己
  的移动包先到（UDP 乱序），允许用一个"贴合已接受位置且不让攻击者占便宜"的
  声称原点修正，但不给任何额外射程。
- **受害者位置**从历史位置里选，客户端的 `victim_pos` 只用于挑选参考点，
  伪造它换不到射程。
- 命中要求距离在 `range` 内 **且** 服务端视线通畅。所以"隔墙打人""超远打人"都会被拒。

### 4. 嫌疑打分而非当场封号

每次违规按类型累加权重，按半衰期衰减（默认 90 秒），达到阈值才 `watch`/`ban`。
`wall_graze` 只有 0.3 分，抖动引起的偶发擦墙会自然衰减掉，不会积累成封号。
`Aegis.Rules` 里集中了所有阈值，按游戏数值调参即可。

## 压测

`Aegis.Sim.Runner` 是一个**离散事件**模拟器：每个 tick 让所有 actor 产生客户端会发的包，
`Aegis.Sim.Net` 按 `发 + 延迟 + 抖动` 投递并按丢包率丢弃，服务端按到达顺序调用
**和线上完全相同的** `Aegis.Validator`。

合成玩家（`Aegis.Sim.Actor`）：

| profile | 行为 | 期望 |
|---|---|---|
| `honest` | 沿合法路径正常走、正常开火 | **零误报** |
| `speed` | 2× 速度 | 被抓、封 |
| `teleport` | 每隔几秒瞬移 | 被抓、封 |
| `noclip` | 直穿墙体往返 | 被抓、封 |
| `aimbot_range` | 站原地打射程外目标 | 攻击被拒 |
| `aimbot_wall` | 隔墙打人 | 攻击被拒 |
| `spin` | 每 tick 开火（远超冷却） | 射速被拒 |
| `flash` | 瞬移 + 超距 + 穿墙 | 被抓、封 |

## 实测结果（本机 14 核）

| 场景 | 正常玩家移动误报 | 外挂检测 | 封禁 |
|---|---|---|---|
| 正常链路（50ms/20ms/1%） | **0 / 39404 (0.0%)** | 170/170 | 170/170 |
| 恶劣链路（120ms/80ms/8%） | **0 移动误报**，9 次边界攻击告警，无人被 watch | 170/170 | 170/170 |

判定内核单核吞吐：**≈ 61 万次移动校验/秒（1.6µs/次）**、
**≈ 146 万次攻击校验/秒**。因为判定是纯函数且按玩家独立，可用
`:erlang.make_ref` 分片到多核近似线性扩展——"每秒几万条"有 10× 以上余量。

## 接进现有服务器

1. 把 `Aegis.Map` + `Aegis.Rules` 放进 `:persistent_term`（只读、无锁）。
2. 每个玩家维护一个 `Aegis.Player` 状态（gen_server / ETS 行 / ECS 组件都行）。
3. 收到上报 → 调 `Aegis.Validator.handle_move/5` 或 `handle_attack/6`，
   把返回的 `verdict.pos` 作为权威位置写回并下发纠正。
4. 服务端事件（击退、传送门）调 `handle_knockback/3`，不要相信客户端事件。
5. `verdict.status` 进入 `:watch` 时记录嫌疑，`:ban` 时走你的封禁流程。

详细说明见各模块 `@moduledoc`，尤其是 `Aegis.Validator` 和 `Aegis.Rules`。
